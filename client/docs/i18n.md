# Internacionalización (i18n) del cliente

Es obligatoria para cualquier texto que vea el usuario en `client/`. `pnpm check` la verifica
(`pnpm check:i18n` en concreto); un cambio que no pase no está terminado.

Estado actual: **español** (`es`) es el idioma base y el único disponible. **Inglés** (`en`) y
**portugués de Brasil** (`pt`) están registrados y preparados, pero vacíos y ocultos del
selector hasta que se completen.

## 1. Regla principal: ningún texto visible se escribe en un componente

```svelte
<!-- MAL -->
<button title="Guardar cambios">Guardar</button>

<!-- BIEN -->
<button title={t('servers.save.hint')}>{t('servers.save.label')}</button>
```

Esto incluye el texto entre etiquetas y los atributos `placeholder`, `title`, `alt`, `label` y
`aria-*`, así como los mensajes que se construyen en `<script>` para mostrarse (toasts, errores,
`<title>`).

No se traducen:

- **Marca**: `APP_NAME` / `APP_SHORT_NAME` de `$lib/app`.
- **Nombres de idioma**: se muestran en su propio idioma ("English", "Português"); salen del
  registro `LOCALES`.
- **Datos del usuario o del sistema**: nombres de servidores o de units de systemd, rutas,
  salida de logs.
- Texto para desarrolladores que el usuario no ve (`console.*`).

## 2. Arquitectura

```
src/lib/i18n/
  messages/
    es.ts           Idioma BASE: fuente de verdad de claves y parámetros (as const)
    en.ts           Traducciones parciales: `{ … } satisfies Translation`
    pt.ts
  locales.ts        Registro de idiomas (código, autónimo, etiqueta Intl, disponible) y cargadores
  types.ts          Tipos: claves válidas y parámetros deducidos de es.ts
  translate.ts      Lógica pura: búsqueda, plurales, interpolación y respaldo
  i18n.svelte.ts    Estado reactivo (runes): idioma, preferencia, `t()`
  format.ts         Números, bytes, porcentajes, fechas y tiempos relativos con Intl
  index.ts          API pública: importar siempre desde `$lib/i18n`
```

- **Sin dependencias.** No se usa Paraglide porque sus plugins se descargan de un CDN y se
  ejecutan al compilar (riesgo de cadena de suministro, y no compila sin red). Tampoco
  `svelte-i18n`, que se basa en stores de Svelte 4.
- **Tipado estricto.** `t()` solo acepta claves que existen en `es.ts` y exige exactamente los
  parámetros que usa su texto. Una clave mal escrita o un parámetro olvidado es un error de
  compilación (`svelte-check`).
- **Reactivo.** `t()` y las funciones de `format.ts` leen el idioma activo: al cambiarlo, la
  interfaz se actualiza sin recargar y sin perder el estado.
- **Carga diferida.** `es` se empaqueta siempre; cada otro idioma es un chunk aparte que se carga
  al seleccionarlo. `src/routes/+layout.ts` espera el idioma guardado antes del primer render.
- **Respaldo.** Una clave sin traducir muestra el texto en español, nunca una clave vacía.
- **Preferencia.** "Sistema" (por defecto) elige el primer idioma disponible de
  `navigator.languages` (`pt-BR` → `pt`) o, si no hay ninguno, el español. La elección se
  guarda en `localStorage` (`blacksmith:locale`) y `<html lang>` se mantiene sincronizado.

## 3. Uso

```svelte
<script lang="ts">
    import { formatBytes, formatRelativeTime, t } from '$lib/i18n';

    let { server }: { server: Server } = $props();
</script>

<h2>{t('servers.detail.title', { name: server.name })}</h2>
<p>{t('servers.services', { count: server.services.length })}</p>
<p>{formatBytes(server.memoryUsed)} · {formatRelativeTime(server.lastSeen)}</p>
```

- **Parámetros**: `{nombre}` en el texto y `t(key, { nombre })`. Los números se formatean solos
  según el idioma (`1.234.567` en `pt-BR`).
- **Plurales**: un objeto con categorías de `Intl.PluralRules` (`one`, `other`, y `zero`,
  `two`, `few` o `many` si el idioma las usa). `other` es obligatoria y el texto usa `{count}`:

    ```ts
    services: { one: '{count} servicio', other: '{count} servicios' },
    ```

    Nunca `count === 1 ? … : …` en el componente: las reglas de plural cambian de un idioma a
    otro.

- **Números y fechas**: siempre con `formatNumber`, `formatBytes`, `formatPercent`,
  `formatDateTime` y `formatRelativeTime`. Nunca `toFixed`, `toLocaleString()` sin idioma ni
  "hace X min" a mano.
- **Claves dinámicas**: solo con un tipo cerrado que el compilador pueda comprobar, p. ej.
  ``t(`theme.names.${id}`)`` con `id: ThemeId`. Si se añade un tema sin su nombre, no compila.
- **Nunca `{@html t(...)}`**: los mensajes son texto plano. Para resaltar parte de una frase,
  se divide en varias claves o se usan snippets.
- **Errores del agente**: no se muestra el `message` que devuelve la API. Se traduce el `code`
  (`ErrorCode` de `shared`) con la clave `errors.agent.<CODE>`.

## 4. Claves

- Jerarquía por pantalla o área funcional: `dashboard.empty.title`,
  `servers.form.host.label`. `common.*` solo para lo realmente compartido ("Guardar",
  "Cancelar", "Sistema").
- `camelCase` en cada segmento. Describe el **propósito**, no el texto: `servers.delete.confirm`,
  no `servers.areYouSure`.
- Una clave por uso. Que dos textos coincidan hoy en español no implica que coincidan en otro
  idioma.
- Ningún grupo de claves puede llamarse `other`: está reservado a los plurales.
- Frases completas en una sola clave, con parámetros. Nunca se concatenan trozos traducidos
  (`t('a') + nombre + t('b')`): el orden de las palabras cambia entre idiomas.

## 5. Flujo de trabajo

**Añadir texto**: escribir la clave en `es.ts` y usarla con `t()`. No hace falta tocar `en.ts`
ni `pt.ts`: hasta que se traduzca, muestran el español.

**Traducir**: copiar en `en.ts` / `pt.ts` la misma estructura de `es.ts` con el texto traducido,
manteniendo los mismos `{parámetros}` y la forma (texto o plural). Las categorías de plural
pueden variar: el portugués e inglés usan `one`/`other`; otros idiomas, más.

**Publicar un idioma**: cuando `pnpm check:i18n` muestre que está completo (p. ej. `en 42/42`),
poner `available: true` en `LOCALES`. A partir de ahí, una clave nueva sin traducir en ese
idioma es un error. `I18N_STRICT=1 pnpm check:i18n` exige que todos estén completos.

**Añadir un idioma**:

1. Crear `messages/<code>.ts` con `export default {} satisfies Translation;`.
2. Añadirlo a `LOCALES` (código, autónimo, etiqueta `Intl`, `available: false`) y a `LOADERS`
   en `locales.ts`.
3. Traducirlo y pasarlo a `available: true`.

## 6. Qué comprueba `pnpm check:i18n`

| Comprobación                                                           | Resultado                         |
| ---------------------------------------------------------------------- | --------------------------------- |
| Texto o atributo visible escrito a mano en un `.svelte`                | Error                             |
| Clave de una traducción que no existe en `es.ts`                       | Error                             |
| Traducción con otros `{parámetros}` o con otra forma (texto vs plural) | Error                             |
| Plural sin `{count}` en `es.ts`                                        | Error                             |
| Idioma registrado sin archivo, sin cargador o archivo sin registro     | Error                             |
| Idioma `available: true` con claves sin traducir                       | Error                             |
| Idioma en preparación con claves sin traducir                          | Aviso (error con `I18N_STRICT=1`) |

Las claves inexistentes y los parámetros incorrectos en `t()` los detecta `svelte-check`.

## 7. Fuera del alcance actual

Los textos que se generan en Rust (menús nativos, diálogos o notificaciones de Tauri) no pasan
por este sistema. Cuando existan, el idioma activo se le enviará al backend por un comando de
Tauri y se traducirán allí con sus propios catálogos.
